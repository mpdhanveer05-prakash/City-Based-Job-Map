### 2026-10-01: P2-05 Animation engine (work log, before the final verification above)
- **Added in `code/map/animation/`:** `easing.ts` (ease-out and ease-in cubic, the 280 / 220 / 120 / 200 / 100 ms timings, the 250-item limit), `animator.ts` (the engine), `targets.ts` (worker response to targets). - **How it behaves (map-spec §4):** each key has one transition segment, and a new update starts every segment from the item's **current** interpolated state, so nothing snaps back. Zoom in: children are born at their parent, at no size and no opacity, and grow to their own place over 280 ms ease-out while the parent shrinks away. Zoom out: the reverse over 220 ms ease-in, with the new cluster growing in where it is. A new `dataVersion:filterHash` namespace cross-fades the old scene out where it is and the new one in (200 ms); an office that is in both result sets keeps its key and does not flicker. A pan fades items in and out over 120 ms; a jump of several levels cross-fades. More than 250 moving markers cross-fade and set `degraded`. Reduced motion: no movement, a 100 ms opacity change at most. An update older than the latest applied generation is ignored. The render list is a map by key, so a key is drawn once.

  - `npm run lint`, `npm run typecheck`: pass. `npm test`: **230 passed** (9 files; 28 new in `tests/unit/animator.test.ts`, on a fake clock: easing, first draw, pan, split, merge, reversal mid-split, a fade-out that returns, a **randomized property test** that no item's position, scale, or opacity jumps when an update arrives at any moment, filter change, jump, stale generations, the 250 limit, reduced motion, sampling order, reset).
