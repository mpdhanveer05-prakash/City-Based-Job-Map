## 3. Commands that destroy data or reach production

| Command | What it does | Instead |
| --- | --- | --- |
| `npx supabase db reset` (from `code/`) | **Wipes the main local database** (the pilot drafts) and loads the synthetic seed. Nothing in code prevents it | `node scripts/test-stack.mts reset` (test stack only) |
| `npx supabase test db` | Runs pgTAP on the main database (each file rolls back, but it is the wrong target) | `npm run test:db` (guarded) |
| `npx supabase stop --no-backup` | Deletes the main volume | plain `npx supabase stop` |
| `npx supabase migration up --local` | Changes the main database | only with the owner's approval and a fresh dump first (PROJECT_HANDOVER §14.1) |
| **`npx wrangler deploy`** with no `--env` | Deploys the **production** Worker `company-map` (`code/wrangler.jsonc:6`) | never by hand; production goes through `deploy-production.yml` only |
| `npm run deploy:staging` | Deploys staging, bypassing `check-deploy-env`, smoke tests and the reviewer | the Deploy staging workflow, with the owner's approval |
| `npx wrangler rollback` | Changes what a live site serves | owner's approval |
| `python -m scripts.pilot.verify_research` | Re-fetches pages and **overwrites the tracked** `candidates.json` and `verification.json` with today's results | only when the owner asks for a new verification round |
| `python -m scripts.pipeline.cli …` with `PIPELINE_DATABASE_URL` set | Writes jobs, evidence and heartbeats to whichever database the URL names; the CLI has no target guard | pytest on the test stack |
| `python -m scripts.pilot.build_import --import` | Imports drafts into a local database and creates a persistent stand-in editor there | only for the pilot re-import (NEW_MACHINE_SETUP C3) |

The comments in `code/vitest.parity.config.ts:4` and `code/tests/parity/filter-parity.test.ts:14,94` still say to run

## 4. Habits that avoid false results

- Kill stale `wrangler`/`workerd` before e2e: Playwright reuses :3100 and would test an old `out/`
  ([feedback-stale-test-server](../claude-memory/feedback-stale-test-server.md)).
- Running `next dev` corrupts the generated types: `rm -rf .next/dev/types && npx next typegen` before a build.
- E2E: 3 workers locally (2 in CI); 60 s timeout (120 s for logo and animation specs). Use the `hold` gate or `__layerNow`
  clock, never fixed delays. Read WebGL pixels in a `render` handler. Check that a new test can fail
  ([feedback-e2e-suite-conventions](../claude-memory/feedback-e2e-suite-conventions.md)).
- Keep measurements that must survive in `gate-results/`: Playwright empties `test-results/`
  ([feedback-playwright-wipes-test-results](../claude-memory/feedback-playwright-wipes-test-results.md)).
- Before `npm run test:admin`: `node scripts/test-stack.mts reset`. Never run it alongside `test:db`
  ([feedback-admin-e2e-and-local-stack](../claude-memory/feedback-admin-e2e-and-local-stack.md)).
- Windows PowerShell 5.1: assigning `''` to an environment variable deletes it. Use Git Bash for "set to empty".
- Timings and memory figures belong to the machine that measured them. The new laptop has far more memory than the old
  one (31.7 GB against about 2 GB free), but still run one full e2e at a time.
